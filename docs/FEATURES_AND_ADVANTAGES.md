# 功能、UI 优势与方案对比

## 功能矩阵

### 可视化与 HUD

- 玩家/生物 ESP：方框、名称、距离、生命值、追踪线和范围过滤；
- 装备显示：装备槽、材质区分与耐久度；
- 床 ESP：床、黑曜石保护层、范围、颜色、透明度和完整高度模式；
- 火球预测：已存在火球轨迹、手持火球预览、轨迹长度和实体数量限制；
- 弓箭锁定显示：锁定角标、颜色、速度、尺寸和线宽；
- 目标列表：玩家/生物筛选、最大数量、字体、背景和 HUD 位置；
- 目标 HUD：血量、距离、装备、附近玩家卡片、横向/纵向布局和入场动画；
- 已启用模块列表：中英文、字体、圆角、颜色、透明度和 HUD 位置；
- HUD 编辑器：拖动并保存各 HUD 元素位置。

### 战斗与输入辅助

- 自动瞄准：距离、视角、平滑度、强度、水平/垂直速度、队伍判断和容器暂停；
- 弓箭瞄准：弹道预测、蓄力阈值、范围、视角、平滑度、队伍判断和视线检查；
- 左/右键连点：最小/最大 CPS、随机抖动、按住触发和方块限定；
- 快捷珍珠、快捷火球；
- 可配置击退节奏控制；
- 边缘潜行：延迟、俯角判断与只在地面启用。

### 背包与容器

- 箱子管理：速度、黑名单、二次确认、两遍扫描、自动关闭和完成退出；
- 背包管理：武器/工具/方块/弓/水桶/珍珠/火球/金苹果等热栏规划；
- 自动盔甲、劣质装备处理、自定义名称保护、投掷物与桶数量保留；
- 手动输入暂停、随机延迟和操作后读取确认，降低误操作风险。

### 桌面与界面

- 跟随 Minecraft 窗口的桌面宠物；
- 启动动画与环境背景特效；
- 单窗口、瀑布式、工作台三套设置 UI；
- 自定义主题、背景、面板、文字、强调色、透明度、缩放和抗锯齿；
- 每模块独立热键、热键冲突清理和右键快捷模式菜单；
- 运行诊断日志和工作台实时日志窗口。

> 自动输入相关功能只应在单机、私人环境或明确允许的服务器中使用。

## 三套 UI 的共同优势

1. **同一配置源**：三套 UI 不是三个分支，所有开关和数值都绑定同一 `AppConfig`。
2. **即时切换**：可以按任务在紧凑、并行和专业工作台布局之间切换，不需要重启。
3. **一致主题**：统一色板和模块模型，换颜色后所有界面同步更新。
4. **完整键鼠交互**：搜索、滚动、滑块、左键开关、右键详情/模式选择和键盘导航。
5. **状态持久化**：缩放、窗口位置、面板展开状态和工作台尺寸都可保存。
6. **自绘可控**：不依赖浏览器或 WebView，字体、圆角、动画、命中区域和性能都由本地代码控制。

## 单窗口 UI 优势

- **信息密度高**：分类、模块和详情同时可见；
- **占用面积小**：适合较低分辨率或边玩边改设置；
- **路径明确**：从分类到模块再到参数，适合首次使用；
- **搜索效率高**：一个搜索框覆盖全部分类；
- **滚动互不干扰**：模块列表和详情区有独立滚动状态；
- **缩放稳定**：所有命中与绘制使用逻辑坐标，缩放后仍保持比例。

## 瀑布式 UI 优势

- **并行观察**：多个分类和模块可以同时展开；
- **自由布局**：面板可以按个人习惯拖放；
- **常用项直达**：不需要反复切换分类页；
- **模块上下文完整**：设置直接在对应模块下展开；
- **适合直播/截图**：各分类形成清晰的视觉分组；
- **布局可恢复**：位置、显示和展开状态保存在配置中。

## 工作台 UI 优势

- **多窗口分工**：搜索、分类、模块、参数和日志互不遮挡；
- **专业调试能力**：实时日志与设置同屏，便于排查数据源和渲染问题；
- **八方向缩放**：每个工具窗都能调整到合适的信息密度；
- **磁吸与弹簧**：靠近游戏边缘或其他窗口时自动对齐，同时保留平滑视觉反馈；
- **大屏效率**：可以把模块列表、检查器和日志长期固定在不同区域；
- **强状态反馈**：开关脉冲、行闪烁和弹簧动画让操作结果更明显；
- **独立故障面**：单个工具窗口的内容刷新不会阻塞整个设置布局。

## 相比普通 Minecraft 客户端/Mod 的优势

这里的“普通客户端”指需要放入 `mods`、修改游戏安装、注入游戏进程或把全部功能运行在 Minecraft JVM 内的方案。不同项目目标不同，以下是架构层面的优势，不代表规避任何安全系统。

### 1. 不修改游戏安装

- 不需要替换 Minecraft JAR；
- 不需要向 `mods` 目录安装文件；
- 不依赖 Forge/Fabric 模组加载生命周期；
- 删除独立程序即可停止使用，游戏目录更容易保持原状。

### 2. 与游戏崩溃域分离

- UI、日志和大部分控制逻辑运行在独立 .NET 进程；
- 覆盖层崩溃通常不会直接带崩 Minecraft JVM；
- Java 堆和 .NET 堆互相隔离；
- 可以单独重启覆盖程序而不重新启动游戏。

### 3. 只读状态采集更易审计

- 内存层只有 `OpenProcess`/`ReadProcessMemory` 路径；
- 没有远程分配、远程线程或进程内 Hook；
- 源码可直接搜索确认没有写进程内存；
- 读取失败时返回空快照和诊断，不修改游戏状态补偿。

### 4. UI 自由度更高

- WinForms 工具窗可以摆放在游戏窗口外部；
- 工作台可同时显示日志、分类、模块和参数；
- 不受 Minecraft GUI 缩放、游戏帧率或聊天界面层级限制；
- 三种 UI 可服务不同屏幕和使用习惯。

### 5. 渲染和游戏循环解耦

- 覆盖层使用独立 GDI+ / layered window 提交；
- 设置窗口和日志不会进入 Minecraft 的渲染线程；
- 可以为床扫描、实体刷新、日志和动画设置不同频率；
- 当游戏最小化或数据无效时可独立降级。

### 6. 发布与回滚简单

- 自包含单文件 Windows x64 发布；
- 不需要用户另装 .NET Runtime；
- 配置集中在 LocalAppData；
- 正式包、测试包和源码可以独立归档及校验哈希。

### 7. 原创性和可维护性更清楚

- C# 模块按功能目录分离，代码规模和职责清晰；
- 三套 UI 共用模型，减少复制粘贴式分叉；
- 发布产物、备份、截图和重建日志可以互相印证；
- 第三方视觉参考与本项目实现范围单独声明。

## 相对普通客户端的取舍与局限

为了避免只写宣传，本项目也公开其限制：

- 外部读取依赖 Java/HotSpot/Minecraft 布局，兼容性不如直接使用稳定 Mod API；
- 分层窗口会受到 Windows 合成、全屏模式和多显示器 DPI 的影响；
- GDI+ 不适合高复杂度 3D 渲染，主要定位是 2D 覆盖与 HUD；
- 独立进程仍然可能被服务器规则、平台政策或安全软件视为不允许工具；
- Windows 输入模拟不是游戏内部事件，焦点变化时必须主动暂停；
- 本项目不保证“不可检测”“绕过反作弊”或任何账户安全结果。

## 适合场景

- 单机、私人服务器、开发测试和允许外部 HUD 的环境；
- 学习 Windows 分层窗口、GDI+、HotSpot 元数据和跨进程只读采集；
- 需要独立日志、三种可切换 UI 和可视化配置的桌面工具。
