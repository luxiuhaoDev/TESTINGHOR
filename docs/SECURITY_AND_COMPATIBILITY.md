# 安全边界、兼容性与风险

## 关于“绕过”的说明

本仓库不提供规避反作弊检测、隐藏进程访问、绕开封禁、伪造输入来源或对抗安全软件的操作教程。原需求中的“绕过方式”在公开文档中统一解释为：**如何在不修改游戏文件的前提下实现外部兼容、窗口穿透和故障隔离**。

## 合规兼容机制

- **游戏文件隔离**：不替换 JAR，不安装 Forge/Fabric Mod；
- **窗口点击穿透**：覆盖层使用 Windows 扩展样式，使鼠标事件继续到游戏窗口；
- **不抢焦点**：覆盖窗和 HUD 默认不激活；
- **只读进程权限**：内存采集不请求写权限；
- **数据降级**：识别失败时停止对应渲染并记录诊断；
- **输入门控**：游戏失焦、容器打开或配置条件不满足时暂停部分自动输入；
- **用户可关闭**：每个模块独立开关和热键，配置可删除恢复默认。

## 运行风险

- 外部工具仍可能违反服务器或平台规则；
- 自动输入可能导致误操作、账号处罚或与其他软件冲突；
- 读取 HotSpot 内部结构存在版本兼容性风险；
- 安全软件可能对进程读取或输入模拟报警；
- 全屏独占、DPI、显卡驱动和多显示器会影响覆盖窗口；
- 本项目不承诺“绕过”“不可检测”“无封禁”或“适配所有客户端”。

## 推荐使用范围

- 单机游戏；
- 私人服务器；
- 明确允许辅助工具的环境；
- UI、渲染、JVM 结构研究与测试。

## 隐私

- 配置和日志位于 `%LocalAppData%\TESTING HOR DESKTOP PET FEATURES\`；
- 提交 Issue 前检查日志中的窗口标题、用户名、路径和服务器信息；
- 仓库 `.gitignore` 排除本地配置、日志、备份和正式成品；
- 不应上传账号令牌、私有服务器地址或封禁通知中的个人信息。

## 报告安全问题

请不要在公开 Issue 中发布可直接滥用的漏洞细节。先通过 `luxiuhaoDev` 的公开 GitHub 联系方式说明影响、复现条件和建议修复。
